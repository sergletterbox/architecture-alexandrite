# Мотивация

## Почему необходим комплексный мониторинг

- Нет данных о техническом состоянии систем, система медленно работает, но мы узнаем об этом от пользователей. Память/CPU постепенно растут, пока не упадет сервис.
- Невозможно предсказать и предотвратить инциденты
- Потерянные заказы - не знаем, на каком этапе и почему теряются заказы


# Выбор подхода к мониторингу

## 1. RED метрики для API сервисов (Shop API, CRM API, MES API)

**RED = Rate, Errors, Duration**

**Почему RED для API:**
- Это request-driven сервисы
- Фокус на пользовательском опыте
- Простота интерпретации для бизнеса


## 2. USE метрики для инфраструктуры (БД, RabbitMQ)

**USE = Utilization, Saturation, Errors**

**Почему USE для инфраструктуры:**
- Помогает найти bottlenecks в ресурсах
- Предсказывает проблемы до их возникновения
- Критично для capacity planning

# Метрики по компонентам системы

## 1. RabbitMQ - критичный компонент интеграции
### Количество сообщений, которые не удалось обработать. Ярлык - имя очереди
### Сообщения, которые доставлены consumer'у, но не подтверждены (ACK). Высокое значение указывает на проблемы обработки (долгие задачи, зависания). Ярлык - имя очереди


## 2. API Services 

### Response time (latency) - p50, p95, p99
**Shop API, CRM API, MES API**

**Зачем нужна:**
- Прямо влияет на user experience
- Раннее обнаружение деградации производительности

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
endpoint: [/orders, /orders/:id, /calculate-price]
method: [GET, POST, PUT, DELETE]
status_code_class: [2xx, 4xx, 5xx]
user_type: [b2c, b2b, internal]  # для Shop/MES API
client_id: [partner_123, partner_456]  # для B2B через API
```

### Number of HTTP 500 errors

**Зачем нужна:**
- 5xx = серверные ошибки = проблема на нашей стороне
- Каждая 500 ошибка = потенциально потерянный заказ или плохой UX

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
endpoint: [/orders, /orders/:id, /calculate-price]
error_type: [database_timeout, rabbitmq_connection_error, internal_error]
status_code: [500, 502, 503, 504]
user_type: [b2c, b2b]
```

### Number of requests (RPS) 
**Shop API, CRM API, MES API**

**Зачем нужна:**
- Показывает нагрузку на систему
- Помогает выявить аномалии (DDoS, внезапный спад)
- Можно использовать для capacity planning

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
endpoint: [/orders, /orders/:id, /calculate-price]
method: [GET, POST, PUT, DELETE]
user_type: [b2c, b2b, internal]
```

## 3. Базы данных

### Number of connections - shop_db, mes_db 
**Зачем нужна:**
- PostgreSQL имеет лимит connections (обычно 100-200)
- Connection pool exhaustion = невозможность обработать запросы
- Ранний индикатор проблем (connection leak)

**Ярлыки:**
```
database: [shop_db, mes_db]
state: [active, idle, idle_in_transaction, waiting]
application: [shop_api, crm_api, mes_api]
```


### Size of database instances 
**Зачем нужна:**
- Предсказание заполнения диска
- Планирование миграций и апгрейдов
- Оптимизация хранения (очистка старых данных)

**Ярлыки:**
```
database: [shop_db, mes_db]
type: [total_size, table_size, index_size]
top_tables: [orders, customers, order_files]
```

## 4. Ресурсы приложений

#### CPU % - shop_api, crm_api, mes_api 
**Зачем нужна:**
- Индикатор нагрузки на приложение
- Помогает определить необходимость масштабирования

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
instance_id: [i-123456, i-789012]  # для multiple instances
```
### Memory Utilisation - shop_api, crm_api, mes_api 
**Зачем нужна:**
- Детектирование memory leaks
- Предотвращение OOM (Out of Memory)
- Capacity planning

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
instance_id
```

## 5. S3 Storage (3D файлы)

#### Size of S3 storage 
**Зачем нужна:**
- Прогнозирование затрат
- Выявление аномального роста (возможно duplicate uploads)

## 6. Сессии и трафик

### Number of simultaneous sessions 
**Shop API, CRM API, MES API**

**Зачем нужна:**
- Понимание concurrent users
- Capacity planning
- Выявление аномалий (bot traffic)

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
user_type: [authenticated, anonymous]
device_type: [desktop, mobile, tablet]
```

### Kb transferred (received/sent) 
**Shop API, CRM API, MES API**

**Зачем нужна:**
- Оптимизация bandwidth costs
- Выявление heavy endpoints
- Детектирование аномального трафика

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
endpoint: [/files/upload, /orders, /dashboard]
direction: [inbound, outbound]
```
## 7. Метрики для оптимизации

### Number of requests per user (RPS per user) 
**Shop API, CRM API, MES API**

**Зачем нужна:**
- Выявление abuse (один user делает слишком много запросов)
- Rate limiting для API клиентов
- Понимание behavior patterns

**Ярлыки:**
```
service: [shop_api, crm_api, mes_api]
user_id: [хэшированный для privacy]
user_type: [b2c, b2b]
client_id: [для B2B API клиентов]
```
